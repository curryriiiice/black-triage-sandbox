## Failures explained

- **c02 (FAIL, spam treated as needs-info).** The body is the untouched bug template, and the title is an
  unrelated Spanish phrase. The agent noticed the template, but read the placeholder snippet as Black content.
  So it posted a needs-info comment, where the policy says spam gets no comment. The harm is low (no wrong
  component label), but the agent still posted on a spam issue. Suggested fix: in SKILL.md, a body that only
  repeats the template placeholders (`this = "code"`, empty sections) counts as "no Black-specific content".
- **c06 (FAIL, real crash not reproduced).** The agent's reasoning matched its tool output. The tool was wrong
  for the date: `repro_black.py` pins only `black==25.12.0`, so pip installs today's `pytokens` 0.4.1. That
  release contains the later tokenizer fix. The tester verified locally that Black 25.12.0 + `pytokens==0.3.0`
  (current on 2026-01-07) fails with exactly the reported
  `Cannot parse for target version Python 3.13: 3:0: 2`. This is hindsight leakage through dependencies.
  Builder fix: resolve dependencies as of the issue date, e.g. `uv pip install --exclude-newer <date>`, or
  pin constraints from PyPI upload times.
- **c08 (FAIL, missed duplicate).** The original (#9, the c07 replay) was in the candidate list, but ranked
  last (lexical score 0.041). The titles share almost no words, and the original's body at creation never
  mentions encoding. The agent did not link it. This needs semantic duplicate search, or a signal for "same
  release regression". Lexical ranking alone cannot catch it.
- **c17 (PARTIAL).** This is the pre-registered alternative. The agent cannot know that the referenced
  upstream number is a merged PR, so it asked for a repro instead of labelling spam.
